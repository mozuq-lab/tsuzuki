# タスクと資料の決まり

~/tasks には、タスクごとのフォルダーと資料を置く。資料や引き継ぎを書く前に、この決まりを読む。

## フォルダーの作り方と名前

- タスク1つにつき、~/tasks の直下にフォルダーを1つ作る。名前は `YYYY-MM-DD-<短い名前>` で、日付は作った日（`date '+%Y-%m-%d'`）にする
- 短い名前は英小文字・数字・ハイフンで書く。空白とチケット番号は入れない
- 作るときは `tsuzuki task new <短い名前> --title <題>` を使う（`--ticket <番号>`・`--repo <パス>` も付けられる）。tsuzuki が使えなければ、フォルダーと下の形の task.md を自分で作る
- 作った後は名前を変えない。変えると別のタスクとして扱われる
- `shared` と、`.` か `_` で始まる名前のフォルダーは、タスクとみなされない

## task.md（表紙）の形

```markdown
---
title: <題>
ticket: "#123"
stage: チケット
waiting: false
repo: <主なリポジトリの絶対パス>
created: YYYY-MM-DD
updated: YYYY-MM-DDTHH:MM
---
# <題>

## 目的

## 現在地

## 次の一手

## 待っていること
なし

## 決めたこと

## 資料
```

- 先頭の `---` で囲んだ見出し情報には、1行に `キー: 値` を1つ書く。YAML のほかの書き方は使わない。値がなければ `ticket:` のように空にする
- ticket：`"#123"` のように引用符で囲む。複数あるときは1行に `, ` で区切って並べる（`ticket: "#123, #456"`）。URL でもよい
- stage：`チケット`・`調査`・`調整`・`実装`・`PR`・`修正`・`完了` のどれか。この順に進むが、飛ばしても戻してもよい。調整は関係者とのすり合わせ、修正は PR の指摘への対応を指し、実装はテストを含む
- waiting：返事やレビューを待っている間だけ `true` にする
- workspace：VS Code で開くワークスペース（`.code-workspace` の絶対パス）。Tsuzuki の画面で決める。書き換えたり消したりしない
- created：作った日
- updated：現在地か次の一手を書き直すたびに、`date '+%Y-%m-%dT%H:%M'` の結果にする
- 作業ブランチを作ったら、`branch: <ブランチ名>` の行を足す
- 6つの見出しは名前を変えず、消さない。ほかの見出しは足してよい

各見出しの下に書くこと：

- 目的：やることと完了の条件。チケットがあれば、その要点
- 現在地：何が終わり、何が途中か
- 次の一手：次にすること。1行目は、次の会話の最初にすること
- 待っていること：誰の何を待っているか。なければ「なし」
- 決めたこと：決めたことと理由。足していき、消さない
- 資料：フォルダーの外の資料を `- <絶対パス> <説明>` の形で1行ずつ書く。フォルダーの中の資料は書かなくてよい

## 資料の置き場所と名前

タスクの資料は、そのタスクのフォルダーに置く。名前の先頭の語で種類を表す。

- `research-<内容>.md`：調査
- `design-<内容>.md`：設計書
- `plan-<内容>.md`：計画
- `review-<内容>.md`：PR のレビューへの対応
- `notes-<内容>.md`：メモ（調整の記録など）

`<内容>` は英小文字とハイフンで短く書く（例：`research-session-expiry.md`）。

複数のタスクで使う資料は、同じ名前の付け方で ~/tasks/shared/ に置く。中にフォルダーを作ってもよい。使うタスクの task.md の `資料` に、そのパスを書く。

## 引き継ぎは task.md に書く

- `現在地`・`次の一手`・`待っていること` を、その会話の内容で書き直す。`決めたこと` には、新しく決めたことを足す
- 書き直す欄は、箇条書きで3〜7行にする。待っていることがなければ「なし」とだけ書く
- `stage` と `waiting` を今の状態に直し、`updated` も書き直す
- その会話で作った、フォルダーの外の資料を `資料` に足す

## 作業用のファイル

- コミットしない作業用のファイル（テスト用の SQL、確かめ用のスクリプト、サンプルのデータ、実行結果、ログ、画面の写し）は、その会話のタスクのフォルダーに置く。一時領域（/tmp など）には置かない
- コミットする物（ソースコード、コミットするテスト、設定）は、これまでどおりリポジトリに置く
- 増えたらフォルダーを分けてよい（例：`sql/`・`out/`）。`.` で始まる名前と `build` はカードに並ばないので使わない
- 名前の先頭に資料の種類の語（`research-` など）を付けない
- その場かぎりの中間の出力と、タスクが分からない会話のファイルは、これまでどおりでよい
